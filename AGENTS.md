# Project instructions

Read PRODUCT.md and DESIGN.md before UI work. Preserve the user's Rust and Windows requirements. The current stage is design; a browser mockup does not decide the production UI framework.

Use the quiet Apple-inspired desktop direction from DESIGN.md. Do not override it with generic anti-slop bans on system fonts, white backgrounds, familiar sidebars or restrained translucency. Respect Windows keyboard/window behavior.

Keep design tokens and reusable controls consistent. Use real task-oriented layouts. Distinguish demo data, planned sleep and observed sleep. Missing measurements are not zero. Do not fabricate health or productivity scores.

Do not add integrations with school journals or Apple Health. Manual input and local storage are product requirements. Show and inspect implemented UI before claiming visual verification.
